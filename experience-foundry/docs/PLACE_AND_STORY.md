# Place & Story — optional Experience Foundry improvement pathway

**Reviewed:** 2026-11-09 · **Compatible:** Foundry 0.3 and Experience OS v1.2.1.

This is **a candidate opportunity**, not a compulsory Foundry stage or shared UI skin. Try it only when the visitor needs to understand the actual character of a place before committing time, effort or money.

## Improvement-cycle application

**Diagnose:** Does the existing decision tool distinguish this place from generic scenery? Does it already include its own photo-led story? Is photo duplication the real gap?

**Investigate three outcomes:** a genuinely differentiating photo/story; an improved route/day-choice comparison; and, where legitimate, a reliable current-condition or access signal. Record each opportunity's visitor outcome, reuse, source coverage, effort and failure risk. Never use fake volume or subjective adjectives as proof.

**Compare two credible concepts:** for example, a decision-anchored documentary vignette (immediately visible, no extra tap) versus a contextual field-notes drawer (compact before opening, deeper visual exploration). Both must preserve the existing visitor action. Select based on actual density and mobile reach, not a forced house style.

**Build:** use an exact-place media ledger, original writing grounded in land-manager evidence, and explicit dated-photo/rights labels. A mismatch should yield **no photograph**, not a nearest plausible substitute. Keep the owning repository, source APIs and the rest of the site unchanged unless separately approved.

**Prove:** capture the authoritative baseline and replay *the same stop states* before and after. Demonstrate (1) matching photo, (2) matching story, (3) selection/reversal correctness, (4) restored original decision/link, (5) no-photo and no-JS survival. Separate Node contract evidence from real browser image loading, mobile screenshots, public deployment and measured audience behavior.

**Measure:** photo-source and park-source link clicks, next-specialist handoffs and itinerary continuation as distinct events. Do not measure a programmatic render as a photograph viewed or assert CTR impact from passing code tests.

## Reusable standards vs original creativity

Reuse the [Experience OS Place & Story contract](../../design-systems/experience-os-v1/docs/PLACE_AND_STORY.md) for rights, quality, truth and testing. Design the narrative and interaction around the *tool's* question: waterfall layers, freighter biographies, bird habitat or lake shore history should be **different experiences**, not replicas of the Circle Tour's card.
