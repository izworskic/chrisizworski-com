# Vandenberg Rust/WebAssembly pilot

The Vandenberg rocket-viewing guide has a **real Rust decision engine**, compiled for browsers as WebAssembly. This is deliberately a gradual rebuild: Rust runs the candidate filter and relative venue ranking; accessible HTML, the full six-place editorial guide, Leaflet map, Google Analytics safeguards, canonical URLs and official external sources stay intact.

## Files

- `src/lib.rs`: dependency-free, `no_std` Rust functions for the six-place ordering, category filters, and explicit access-caution categories.
- `../../public/vandenberg-rocket-launch-viewing/viewpoint-engine.wasm.b64`: actual 500-byte Rust/WebAssembly build shipped as portable base64 text.
- `../../public/vandenberg-rocket-launch-viewing/guide-map.js`: loads, verifies and calls the Rust WASM exports, then enhances the existing map. If WASM fails or is disallowed by CSP, the original map and all editorial cards still work.
- `../../tests/vandenberg-rust-wasm.test.js`: instantiates the shipped binary and checks every ranking against the authoritative `lib/vandenberg-viewing.js` location scores.
- `../../scripts/verify-vandenberg-rust-wasm.cjs`: verifies both compiled binaries and the source/asset correspondence.
- `../../.github/workflows/vandenberg-rust-wasm.yml`: compiles using pinned Rust 1.90.0, runs native Rust tests and verifies the compiled WASM using Node before release.

The small base64 wrapper is intentional: the repository's GitHub contents editing workflow accepts UTF-8 files, while browsers can instantiate the decoded bytes without additional framework dependencies or a new build service. This is real Rust output, not WASM generated by JavaScript.

## Build

On a machine with rustup and Node.js:

```sh
rustup toolchain install 1.90.0 --profile minimal
rustup target add wasm32-unknown-unknown --toolchain 1.90.0
rustc +1.90.0 --edition=2021 --test rust/vandenberg-viewing/src/lib.rs -o /tmp/vg-tests
/tmp/vg-tests
rustc +1.90.0 --edition=2021 --crate-type cdylib --target wasm32-unknown-unknown \
  -C opt-level=z -C codegen-units=1 -C lto=fat -C panic=abort -C strip=symbols \
  -o /tmp/vandenberg_viewing.wasm rust/vandenberg-viewing/src/lib.rs
base64 -w0 /tmp/vandenberg_viewing.wasm > public/vandenberg-rocket-launch-viewing/viewpoint-engine.wasm.b64
printf '\n' >> public/vandenberg-rocket-launch-viewing/viewpoint-engine.wasm.b64
node scripts/verify-vandenberg-rust-wasm.cjs --wasm=/tmp/vandenberg_viewing.wasm
node --test tests/vandenberg-rust-wasm.test.js
```

## Contract and limitations

Indices 0–5 are `ocean-park`, `surf-station`, `hancock`, `riverbend`, `beattie`, and `ryon`, matching the authoritative manifest. ABI version 1 exports `vg_site_count`, `vg_engine_version`, `vg_group`, `vg_visible`, `vg_caution`, and `vg_rank`.

`vg_rank(index, goal, marine_concern)` uses existing reviewed family/photography/coastal-affinity scores with a stable tie-break. The optional marine-layer checkbox is **a user's stated concern**, not a weather reading. The scores are **relative comparison only**, never launch visibility predictions, verified park openings, a legal invitation to base property, geospatial routes, or real-time forecasts.

If the six-place inventory changes, update both the authoritative JS source and Rust protocol and bump `vg_engine_version`; the tests deliberately fail otherwise. Do not create separate coordinate catalogs in Rust.

The national Vandenberg mission-specific planner remains the source for a verified launch, pad, schedule, weather reference, and launch-day decisions. The Rust engine does not touch the national API, source recency logic, ads, analytics, privacy, or SEO identity.
