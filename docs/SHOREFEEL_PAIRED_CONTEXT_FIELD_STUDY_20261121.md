# ShoreFeel field science, phase 4: paired evidence join

**Date:** 2026-11-21
**Status:** implemented offline research adapter and synthetic tests. No actual paired beach thermometers, verified sensor permissions, archived prospective candidate forecasts, calibrated beach-air model, or production correction are claimed.
**Public page:** unchanged. This does not run in Vercel and has no new API, paid data source, Redis, advertising, SEO, canonical, map, user-location capture or cron cost.

## What this investment solves

The existing Python field logger tool pairs *observed* beach and inland air temperatures within five minutes. The existing JavaScript `fieldAudit` evaluates a model only when records already contain independent observed beach air, a pre-issued NWS baseline, a pre-issued version-locked model estimate, an event identifier and wind regime. Neither previous tool joined source-provenance-aware local wind and NOAA nearshore water temperature to the paired thermometer evidence.

`scripts/shorefeel-field-context.py` is that offline bridge. It consumes **private local files** only and creates:

1. `descriptive` paired-observation rows, with actual beach-minus-inland air differences and dated local wind and NOAA GLSEA nearshore pixel context, or explicit unknowns.
2. `validationDataset`, a conservative subset matching the *existing* `node scripts/shorefeel-validate-field.cjs` schema with one independent beach reading per valid forecast hour. A valid candidate forecast **must already have been archived and issued before that hour**. No model fit, adjustment, retroactive model prediction or fabricated forecast issue time is produced.
3. Coverage, duplicates, conflicting revisions, out-of-hour samples, missing observations, sensor provenance and permanent `publicationAuthorized: false` / `calibrationAuthorized: false` gates.

The actual model may never consume later wind observations or NOAA water pixels retrieved after issue time as if they had been known at issue time. This adapter uses them only to **stratify retrospective evaluation**. An NWS source must identify an `api.weather.gov` endpoint. Any provided NOAA water record must identify a GLSEA **nearshore pixel**, not a lakewide mean or waterline reading.

## Minimum equipment and ethical operation

The Bay City State Park region is the proposed **geographic pilot**, not a claim that sensors have been deployed on park land or that permissions are granted. Establish two independent calibrated, radiation-shielded dry-bulb loggers; document siting, model/serial, exposure, land manager permission and calibration records. A nearshore logger must be within 200 m of water under the existing field pairing contract, and an inland reference at 200 to 5,000 m from shore, not in the same heat-reflective/sheltered exposure as the beach station. The 420 m reference coordinate in prior tests is illustrative, not an actual installation. Use sampling cadence ~5 minutes, synchronized UTC time and independent instrument records.

For meaningful wind-regime evaluation, separately document an **observed local wind sensor within 2 km** of the beach station, with 1 to 20 m height, measured speed and meteorological **wind-from degrees**. Remote offshore buoy winds may still be valuable context, but they do not pass the local wind gate. Calibration and station metadata are self-reported; code alone does not verify a field instrument.

NOAA NWS COOP thermometry siting: https://www.weather.gov/aly/CoopEquipment and https://www.weather.gov/box/coop. NIST outdoor thermometer shielding/siting: https://www.nist.gov/how-do-you-measure-it/how-do-you-measure-air-temperature-accurately . These are placement references, not permission or equipment approval.

Historical airport wind/temperature data may assist exploration but **cannot replace beach ground truth**. NOAA NCEI's newer GHCNh is the successor to the retired ISD/Global Hourly dataset: https://www.ncei.noaa.gov/products/global-historical-climatology-network-hourly . Before ingesting any future GHCNh archive, check documented provenance, geolocation, quality flags, current access, commercial terms and coverage. No GHCNh ingestion is introduced by this PR.

## Private input contract

A `paired.json` generated by the existing Python `shorefeel-field-pair.py` must retain `shorefeel.paired-air-loggers.v1`, the separately documented `beachStationId` and `inlandStationId`, `records` containing `beachAt, inlandAt, beachAirF, inlandAirF, beachMinusInlandF, independentFieldObservation`, and `stationMetadataIndependentlyVerified: false`. Both unaltered station metadata JSON files are supplied to the next step too.

A separate privately retained `issued.json` has:

- `schema: "shorefeel.issued-air-comparison.v1"`
- `modelVersion` a nonempty locked research version; `modelLockedAt` before `holdoutStartsAt`; `records` an array of independently archived issued forecast records.
- Every record requires `validAt, nwsIssuedAt, modelIssuedAt` (unambiguous UTC Z), `nwsShoreF`, `modelBeachF` (both Fahrenheit), `eventId` (weather-event grouping), matching `modelVersion`, `nwsSourceUrl` from `api.weather.gov`, and `modelSource: "independently-archived-preissued"`.
- Both issue timestamps must be earlier than their valid target, within 48 hours. This contract is not proof of issuance; archive original source bytes, issue timestamps, model code revision/digest and raw sensor audit evidence separately.

A separate `context.json` has:

- `schema: "shorefeel.local-observation-context.v1"`
- `windStation: {role:"local-observed-wind",lat,lon,heightM,permissionDocumented:true}`
- `wind` records: `{observedAt,fromDeg,speedMph,quality:"valid"}`, from a locally documented anemometer.
- `water` records: `{observedAt,tempF,lat,lon,quality:"valid",kind:"NOAA_GLSEA_ACSPO_NEARSHORE_PIXEL",sourceUrl:"https://apps.glerl.noaa.gov/..."}`. The source must be an approved NOAA GLERL host, the pixel between 0.1 and 30 km from the site, and the data timestamp not more than 36 hours before the field observation. These are integrity caps, **not geographic forecast precision**.

Duplicate source records with identical timestamp/key but *different values* are excluded rather than silently overwritten. A duplicate identical record is counted. Beach loggers are matched within five minutes by the existing tool, then one best observation within 15 minutes of a forecast-hour boundary is retained for the evaluation. An observed wind direction within ten minutes of that observation is compared with the approximate bearing **toward the nearshore water pixel**. Within 45 degrees is categorized onshore, beyond 135 offshore, otherwise alongshore. Wind below 3 mph, missing local wind or missing fresh pixel is `unknown` and is not put into the model-skill comparison.

This geometric bearing is **not measured fetch, a coast-normal vector, proof of a lake-breeze front or the wind the forecast model knew at issue time**. A genuinely calibrated shoreline heat-transfer forecast would need more complete measurements and verified pre-issued features.

## Execute (offline, with actual permissioned research files)

```bash
python3 scripts/shorefeel-field-pair.py \
  --beach-meta /private/shore/beach-meta.json \
  --inland-meta /private/shore/inland-meta.json \
  --beach-csv /private/shore/beach.csv \
  --inland-csv /private/shore/inland.csv > /private/shore/paired.json

python3 scripts/shorefeel-field-context.py \
  --paired /private/shore/paired.json \
  --issued /private/shore/issued.json \
  --context /private/shore/context.json \
  --beach-meta /private/shore/beach-meta.json \
  --inland-meta /private/shore/inland-meta.json \
  > /private/shore/study.json

python3 scripts/shorefeel-field-context.py \
  --paired /private/shore/paired.json \
  --issued /private/shore/issued.json \
  --context /private/shore/context.json \
  --beach-meta /private/shore/beach-meta.json \
  --inland-meta /private/shore/inland-meta.json \
  --validation-only > /private/shore/fieldAudit-input.json

node scripts/shorefeel-validate-field.cjs /private/shore/fieldAudit-input.json > /private/shore/holdout-report.json
```

All paths above are **examples**, not files this PR creates. Store real logs, instrument metadata, permissions and model outputs outside the public website repository and Vercel `public/` tree.

## Model decision gate

Even if an offline dataset eventually produces `holdout-reviewable`, no publication is authorized until an independent reviewer verifies sensor deployment/permission, calibration, event independence, source issue-time truth, onshore/offshore case coverage, weather-season representativeness, prospective candidate performance versus the **same** NWS baseline cases, uncertainty and drift. Publish only if out-of-time field skill is meaningfully better, with a clearly stated error bound and unavailable fallback. Otherwise, retain existing NWS ShoreFeel temperatures.

**Next outside-code dependency:** secure verified paired nearshore/inland thermometers and a local wind sensor at an approved Saginaw Bay site. The three existing July/September/November NOAA HRRR/URMA research snapshots are model-grid contrasts, not the field observations needed to calibrate this engine.
