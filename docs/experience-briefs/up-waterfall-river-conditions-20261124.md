# Waterfall intelligence: first investment (2026-11-24)

## Visitor job and design
The existing map, arrival desk, four regional plans and 80 cards solve location and access. The remaining question is whether river conditions have changed. Keep the existing map-first layout. Compared with a prominent waterfall-specific condition dashboard (not supported by gauge-to-falls evidence), a compact, opt-in river reading panel is honest and less intrusive. Unlike the Michigan river tools, this panel compares three explicitly named river stations rather than implying observations at each waterfall. Unlike the Circle Tour, it does not change the itinerary. No destination eligibility, routes, photos, guide URLs, ad settings or schema are altered.

## Source register and schema
USGS public federal water observations: https://api.waterdata.usgs.gov/docs/ogcapi/ and https://www.usgs.gov/information-policies-and-instructions/copyrights-and-credits . Attribution and station links supplied. Daily endpoint v1, parameter 00060, mean statistic 00003, ft^3/s. Stations 04045500 Tahquamenon near Paradise, 04031000 Black near Bessemer, 04032150 Presque Isle near Connorville. These are river measurements, not verified waterfall discharge; no inferred connection to individual falls. No station proximity scoring. Request only 14 calendar days on explicit click, three requests max per click; abort after eight seconds. Schema v1: AVAILABLE (date, daily mean, qualifier, approval, optional seven-day comparison), STALE (date only), UNAVAILABLE (reason). Completed days use Michigan Eastern calendar; three-day freshness limit; no extrapolation, missing means unknown, conflict fails closed, zero is valid, incomplete current days excluded, flagged observations suppress comparisons. USGS revisions and provisional values can change. Comparison is not a seasonal percentile, safety rating or prediction.

## Technology fit
Keep HTML/CSS and small browser JS for the bounded, descriptive request. No new Node endpoint, Python runtime, Rust/WASM or Java; none offers demonstrated value here. Scheduled offline Python/dataretrieval is appropriate for a later validated day-of-year baseline, after checking station continuity, regulation and upstream/downstream reach topology. HF forecast challenger stays offline until an independent measured target and holdout exist. No model, key, cron, database, paid endpoint or new dependency. Rollback: revert this PR. Source API compatibility/CORS and live readings must be checked in browser; direct official links remain when blocked.
