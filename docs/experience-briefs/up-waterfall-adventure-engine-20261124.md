# Town-first waterfall adventure pilot (2026-11-24)

Decision: visitor has a starting town and finite time; compare a compact set of waterfall visits with spending longer at one. Existing visit lens is per-stop, nearby tool is waterfall-to-waterfall discovery, and existing regional presets are fixed. This opt-in mode reuses the same date, verified arrival policy, map focus, original save controls and six-stop itinerary. No second shortlist. Existing map, SEO, schema, ads and guide inventory preserved.

Alternatives: (A) route-first timed itinerary with external road matrix, incomplete verified parking and no reliable driving-time source; reject for now. (B) geography-first candidate outings with visitor-specified travel/break reserve and maximum documented on-site times; choose. Circle Tour's drive itinerary and existing regional day plans are reference patterns, not copied. This is not a verified road route; no estimated road mileage, time, live opening, actual daylight or optimized sequence. A human still checks drive and daylight. No ML, Python or Rust rewrite; bounded enumeration of up to 80 choose 3 is small, existing JS/Rust policy gates remain. No paid services or new infrastructure.

Data: town index is a source-preserving subset of existing Census 2024 Gazetteer place records, northern Michigan bounding box, no township/county or NWS storm report coordinates. Exact unique town name only, native text suggestions, no auto-promotion of ambiguous match. Not all unincorporated communities are covered (Paradise is absent); no unsupported geocoding. Radius is straight-line distance to waterfall point, not parking. Candidate requirements: existing status verify, verified arrival, shared gate, visit review check, known documented max on-site duration and arrival group, walking preference. Explicitly held special approaches, restricted/seasonal states, winter/spring/autumn (June–September only, editorial precaution not legal closure). Same region, max three stops and 15-mile pairwise separation, distinct known shared arrival groups. Shared parking detection uses documented parking text and explicit Presque Isle group; it is not comprehensive route topology. Preference hike requires at least one moderate/steps/difficult route. Compare most stops (tie by proximity) vs longest single stop (if distinct), no invented score. User supplies travel/break reserve; on-site max + reserve <= total is arithmetic, not a promise the trip fits actual travel. Existing save state preserved, fresh policy and capacity checked before adding, no changes to existing card save rules.

Testing: deterministic algorithm cases for budget, town, preference, closures, season, shared approach, source index and malformed data; mobile browser save and winter refusal fixture. Latest merged foundation had five green workflows. New PR verification and real desktop/mobile screenshot review pending. Seasonal basin source validation remains incomplete. No SEO lift or uniqueness claim without competitive research and measured outcomes. Next: verify route inputs from source-backed parking and public road routing, then integrate route durations/daylight and develop verified seasonal outing modes. Rollback: revert PR.
