## Decision and method

Reuse existing OSM-based Soo channel polylines in lib/soo-locks-next.js, tested against island outlines and a dated snapshot; no claim of surveyed navigable geometry. Keep existing production ETA behavior unchanged. Existing JS projection selected over Turf or offline MovingPandas because this bounded three-route experiment needs no new runtime package. Offline Python could support large multi-corridor geometry audits later, not request-time use.

New pure corridor engine separates observed position from inferred model location, abstains near model ends, chambers, ambiguous turns and close divergent branches. Shared local segments preserve multiple route candidates and a range of modeled distances rather than inventing branch choice. Course over ground, not bow heading, supports tentative toward/away classification only for motion with acceptable offset and alignment. Time-ordered adjacent observations of the same MMSI support progress only when both have consistent direction, a common route, enough progress, short gaps and plausible implied speed. No interpolation or tracking across gaps. All thresholds are conservative research choices, not measured probability, physical speed limits or navigation guidance. Pair counts are serially dependent, not independent passages. Low-speed observations remain unresolved, not claimed anchored, waiting or unloading.

Pilot only: Soo Locks. Other waterways need separately reviewed route models, topology and reference points; no invented centerline or public arrival windows. Existing historical Cuyahoga references remain reference-only. All output is offline; no live UI, APIs, map or SEO/ads changes.
