# Michigan Ski Hills | Redundancy and synchronized map carousel | 2026-11-24

## Decision and ownership

The canonical page remains `/michigan-ski-hills/`, generated by `scripts/generate-michigan-ski-pages.mjs`. Existing Node/NWS/approved operator sources, 17 downhill plus one Nordic destination, 2026-27 dated opening announcements, source freshness, Person, ads and search metadata remain intact. Map geometry uses the already committed public state outline and verified resort-coordinate records. No external basemap, API key, new route, new Vercel Function, paid data, additional build step, database, model, or Redis.

The visitor needs one plain answer (which hills have dated operating evidence?), then a practical place-oriented way to browse resorts by area, forecast day and operator opening plans.

## Design options

**A. Map + horizontal carousel (chosen).** Keep the existing geometrically correct SVG map with NWS forecast pin coloring and official status indicated separately. Add one synchronized card carousel, native previous/next buttons, swipe/scroll-snap, keyboard-accessible map markers, clickable card headings, accurate checked/report-date labels, linked official sources, resort detail handoff and optional cost comparison. Existing official-status and region filters narrow both together. In no-JS mode, the full static source table/directory remains accessible.

**B. Replace the map with a full sortable table (rejected).** Reduces visual duplication but removes the spatial distinction between Upper Peninsula and lower Michigan resorts and makes visitor exploration less intuitive. It would offer no coordinate-based selection benefit over the existing collapsed rankings.

Comparison surfaces: Michigan Snow Totals (forecast versus observed evidence and geo scope) and the snowmobile region tools (area selection and source freshness). The carousel is specific to resort selection, not an imposed template.

## One selection spine

Stable identity is each approved `resort.slug`, not a label or ranking. The card, selected SVG pin, selected screen-reader announcement and comparison handoff all use it. Arrow keys on the carousel, native prev/next, swipe scroll, card selection and pin click are reversable A→B→A. The same `region`, `openOnly` and `planOnly` states already used by the operator report board apply to the map. Selecting a day replaces forecast labels without rewriting dated operator statuses.

**Evidence contract:** map dot fill means a forecast amount at an approximate point coordinate. A green/orange outline reflects only a confirmed operator lift report within the existing parser's freshness policy. A positive NWS snow forecast, undated operator count, archival photograph, or operator opening plan never becomes "open now." Mark source and forecast unavailable separately.

**Failure state:** failed outline still leaves text cards and links; failed API falls back to existing static opening table and directory; no-JS hides map controls but leaves static HTML answer and links. A selected resort always has the same ID on the map and card. The browser tests use mocked API fixtures and do not prove live resort status.

## Accessibility and quality

Use semantic buttons and anchors in cards. SVG markers support Enter/Space and retain focus after a keyboard selection. The carousel offers native arrow buttons and a focusable scroll region as alternatives to touch swiping. A short live status announces one resort rather than 18 recreated results. Respect reduced motion and avoid page-level scroll hijack. Verify 360, 390, 768, 1280 and 1440px, 18 pins, reversible selection, filter parity, no-JS links, source outages, outline failure, overflow and keyboard. Inspect screenshots and errors.
