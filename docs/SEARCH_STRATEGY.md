# ChrisIzworski.com Search Strategy Operating System

Updated: August 21, 2026 (America/Detroit)

## North star

ChrisIzworski.com should win search by being the most useful answer for a focused set of Michigan, Great Lakes, outdoor, transportation, gardening, and Chris Izworski entity queries. The strategy is not to publish the most pages. It is to own useful decisions with first-party tools, live data, original synthesis, clear authorship, and a connected network of canonical pages.

**Useful decisions and durable authority, not page-count growth.** That is the operating north star.

Search growth is judged by qualified discovery and use, not by index count alone.

## What the site is building

The search portfolio has four jobs:

1. **Own Chris Izworski as an entity.** The stable Person entity is `https://chrisizworski.com/#person`. Useful owned properties reinforce the same person without creating duplicate branded filler.
2. **Own high-intent Michigan and Great Lakes decisions.** Live conditions, maps, schedules, planners, field tools, and decision pages are the moat. A page should help someone decide or do something, not merely restate a keyword.
3. **Turn seasonal demand into durable authority.** Fall color, winter ice and skiing, spring gardening, summer beaches and boating, rivers, aurora, and shipping should be prepared before demand peaks and connected to year-round authority pages.
4. **Convert visibility into deeper use.** A search landing page should naturally hand visitors to the next useful owned tool, guide, source, or planner rather than operate as an isolated endpoint.

## Strategic hierarchy

When two SEO actions compete, use this order:

1. Protect crawlability, canonical integrity, structured-data validity, performance, and factual accuracy.
2. Protect active experiments and measurement windows.
3. Improve pages already ranking roughly positions 4-15 with meaningful impressions before creating new URLs for adjacent wording.
4. Strengthen the canonical owner of an intent before creating a supporting page.
5. Build a new canonical only for a distinct user decision, evidence-backed search need, or genuinely unique utility.
6. Connect the page into the tool and authority network.
7. Improve branded/entity reinforcement without causing non-branded cannibalization.

## Search portfolio priorities

### P0 — Existing demand near page one

Pages with substantial impressions, average position near page one, and weak or improvable CTR have the highest near-term leverage. The Search Growth Engine and CTR experiment ledger are the source of truth for which treatments are frozen and which pages are eligible for the next test.

The operating pattern is: **measure → improve intent/snippet/usefulness → hold a clean window → decide**.

### P1 — Distinct live utility

Flagship tools should earn links and repeat use because they combine live or difficult-to-assemble information into a clearer decision. Examples include conditions, schedules, maps, river access, fall status, bridge/border status, beaches, buoys, ice, and outdoor planning.

For these pages, SEO work should emphasize:

- a direct answer that survives without JavaScript;
- visible source provenance where risk or freshness matters;
- query-aligned title/H1/first answer without keyword stuffing;
- crawlable explanatory context that helps humans and search systems understand the tool;
- internal links from relevant authority pages and neighboring tools;
- structured data that identifies the page, the WebSite, and Chris Izworski consistently.

### P2 — Seasonal demand capture

Seasonal work begins before the query peak. The site should be ready while search demand is rising, not after it has crested.

- **Late summer / fall:** fall color, fall drives, paddling, salmon/steelhead, whitetail, aurora overlap.
- **Fall / winter:** ice, cross-country skiing, snow/outdoor planning, winter Great Lakes conditions.
- **Late winter / spring:** frost, planting, tomatoes, lawn, phenology, trout season preparation.
- **Late spring / summer:** beaches, boating, launches, paddling, Mackinac/UP travel, Great Lakes recreation.

Seasonal pages remain useful off-season when possible. If a surface cannot provide meaningful year-round value, it should clearly transition into planning context rather than imitate live conditions.

### P3 — Entity and authority

The Chris Izworski branded SERP is protected by a consistent Person entity, source-backed identity pages, press/citation surfaces, Works discovery, and reciprocal links from genuinely useful owned properties. The goal is legitimate entity clarity, not artificial result-slot occupation.

## New canonical URL gate

A new indexable URL should pass all of these tests before launch:

1. **Distinct intent or decision:** the existing canonical owner cannot satisfy the query without becoming confusing or overloaded.
2. **Evidence:** Search Console demand, seasonal evidence, strong external demand, or a clearly documented unique utility supports the build. Evidence may be qualitative for genuinely new live tools, but it must be written down.
3. **Cannibalization safety:** the Tool Network Registry identifies one primary owner for the broad intent and the new URL has a narrower, non-competing job.
4. **Network fit:** the new page has at least two logical inbound/outbound relationships unless it is intentionally a leaf detail page.
5. **Entity integrity:** authorship/publishing relationships point to the canonical Chris Izworski Person entity when appropriate.
6. **Discovery:** canonical, sitemap/discovery surface, crawlable internal link, and indexability are intentional.
7. **Measurement:** the page has a stated success metric and evaluation window.

Do not create doorway pages for cities, counties, dates, or keyword variants unless each page has materially unique, useful information and a distinct decision to serve.

## SERP conversion rules

Ranking is only half the job. For pages already receiving impressions:

- Prefer query-first titles that match the actual decision and remain within the repo title-length guardrail.
- The H1 and first answer should satisfy the same intent as the title.
- Meta descriptions should clarify the unique value, live source, decision, or geographic scope rather than repeat the title.
- Do not churn titles during a running experiment.
- Segment branded and non-branded performance when judging changes.
- Prioritize pages with meaningful impressions and weak CTR relative to position before low-impression speculative rewrites.

## Internal-link strategy

Internal links are an intentional decision network, not a footer-link contest.

Each important landing page should answer: **what is the next useful thing this visitor might need?** Strong links should be contextual and directional: conditions → access, fall color → trip planning, river guide → live river tool, bridge → border/travel context, freighter content → tracking or Gazette, garden guidance → planting/frost/planner.

The Tool Network Registry and owned-domain network are the source of truth. Avoid orphaned flagship tools and avoid excessive reciprocal linking that has no user value.

## Technical SEO standard

Every indexable production page should preserve, as applicable:

- one intended canonical URL;
- indexable production response and no preview-host canonical leakage;
- valid, useful title and meta description;
- one clear H1;
- crawlable core answer/content without requiring client JavaScript;
- structured data with non-dangling entity references;
- sitemap or intentional crawl path;
- image alt text and appropriate lazy loading;
- no accidental `noindex` or preview-domain promotion;
- stable redirects for retired/renamed URLs;
- performance sufficient to keep the tool usable on mobile.

The existing production-readiness and SEO benchmarks remain authoritative for implementation details.

## AI-search and answer-engine readiness

AI discovery is treated as information architecture, not a separate content farm.

- Keep `llms.txt` descriptive and aligned with real canonical pages.
- Give important pages a concise crawlable answer before interactive complexity.
- Use structured data to connect Person, WebSite, Article/WebPage, Dataset, SoftwareApplication, FAQ or other appropriate entities when truthful.
- Prefer source-backed factual statements and explicit update context for live or time-sensitive tools.
- Maintain strong internal entity relationships so a model can understand who built the resource and how related tools fit together.
- Do not add repetitive “AI SEO” prose that makes the page worse for people.

## Measurement operating cadence

### Weekly

- Review Search Console leading indicators without declaring winners early.
- Check indexing/canonical anomalies, crawl failures, broken critical data sources, and performance regressions.
- Review newly emerging query families and map them to an existing canonical owner before proposing a new page.
- Keep unaffected pages moving while protected experiments continue.

### Every complete 28-day window

- Evaluate eligible experiments against their recorded baseline and target.
- Refresh the Search Console baseline with a comparable complete window.
- Separate gains from impression growth, position growth, and CTR growth.
- Promote, iterate, or roll back treatments based on evidence.
- Select the next small set of highest-leverage actions rather than changing the whole site at once.

### Seasonal planning

Begin material seasonal work roughly 6-10 weeks before expected demand. Validate the prior year's pages, data sources, structured data, sitemap discovery, and internal links before building net-new URLs.

## Scorecard

The site-wide strategy is scored on 100 points:

| Pillar | Weight |
| --- | ---: |
| Measurement truth and experiment discipline | 20 |
| Technical crawl/index/canonical integrity | 15 |
| Query ownership and cannibalization control | 15 |
| SERP conversion and intent match | 15 |
| Internal network and authority distribution | 10 |
| Chris Izworski entity / branded SERP integrity | 10 |
| AI-search / structured discovery readiness | 10 |
| Seasonal readiness and freshness | 5 |

A release should not weaken any pillar to inflate another. More indexed pages do not compensate for weaker canonical ownership, worse CTR, or lower usefulness.
